# 02 · 数据模型

> 目标数据库：PostgreSQL 16。金额一律 `NUMERIC(18,2)`，代码侧 `Decimal`。
> 本文是 `apps/api/prisma/schema.prisma` 的权威说明；改 schema 必须先改本文。

## 1. 模型总览（六组）

```
① 组织与科目      Entity · FiscalYear · Period · Account · AuxDimension
② 业务单据        Document · Partner · Contract · Invoice · InvoiceLine
                  BankTransaction · PaymentAllocation · DocumentLink
③ 会计内核        JournalVoucher · JournalLine · VoucherSequence

```

## 2. ① 组织与科目

### Entity（核算主体）

```prisma
model Entity {
  id             String     @id @default(uuid())
  name           String                              // 主体名称
  unifiedSocialCreditCode String?                    // 统一社会信用代码
  taxpayerType   TaxpayerType                        // GENERAL 一般纳税人 / SMALL_SCALE 小规模
  accountingStandard String  @default("SMALL_ENTERPRISE_2013")  // 小企业会计准则
  baseCurrency   String     @default("CNY")
  taxAuthority   String?                             // 主管税务机关
  address        String?
  phone          String?
  legalPerson    String?
  accountantName String?
  fiscalYearStartMonth Int   @default(1)             // 会计年度起始月
  bookkeepingEnforced  Boolean @default(true)        // 是否启用凭证内核的 DB 层强制约束
  createdAt      DateTime   @default(now())
  periods        Period[]
  accounts       Account[]
  @@map("entity")
}
```

### Period（会计期间 = 月）

```prisma
model Period {
  id            String       @id @default(uuid())
  entityId      String
  fiscalYear    Int                                  // 2025
  month         Int                                  // 1..12
  startsOn      DateTime     @db.Date
  endsOn        DateTime     @db.Date
  status        PeriodStatus @default(OPEN)          // OPEN | CLOSING | CLOSED
  closedAt      DateTime?
  closedBy      String?
  reopenedCount Int          @default(0)             // 反结账次数，审计关注点
  entity        Entity       @relation(fields: [entityId], references: [id])
  @@unique([entityId, fiscalYear, month])
  @@index([entityId, status])
  @@map("period")
}
```

> **为什么 `status` 有 `CLOSING` 中间态**：月结是多步骤操作（归集→结转→所得税→锁期）。
> 中途失败必须能断点续跑，且此时不允许再插凭证。`CLOSING` 就是这个"施工中"状态。

### Account（会计科目）

```prisma
model Account {
  id            String        @id @default(uuid())
  entityId      String
  code          String                               // 科目编码，如 "22210101"
  name          String                               // 科目名称
  fullName      String                               // 含上级的完整名称，报表用
  parentId      String?
  level         Int                                  // 1..n
  category      AccountCategory                      // ASSET|LIABILITY|EQUITY|COST|PROFIT_LOSS
  direction     BalanceDirection                     // DEBIT 借 | CREDIT 贷 —— 余额的正常方向
  isLeaf        Boolean       @default(true)         // ★ 只有末级科目允许记账
  isActive      Boolean       @default(true)
  // 报表与申报映射
  reportItem    String?                              // 资产负债表/利润表 行项目标识
  cashflowTag   String?                              // 现金流量表归类（经营/投资/筹资）
  taxTag        String?                              // 增值税归集标记，见 06 章
  auxRequired   AuxDimension[]                       // 必须录入的辅助核算维度
  isSystem      Boolean       @default(false)        // 系统内置科目，不可删除
  sortOrder     Int           @default(0)
  parent        Account?      @relation("AccountTree", fields: [parentId], references: [id])
  children      Account[]     @relation("AccountTree")
  @@unique([entityId, code])
  @@index([entityId, parentId])
  @@index([entityId, reportItem])
  @@map("account")
}

enum AccountCategory { ASSET LIABILITY EQUITY COST PROFIT_LOSS }
enum BalanceDirection { DEBIT CREDIT }
enum AuxDimension { CUSTOMER SUPPLIER EMPLOYEE PROJECT DEPARTMENT CONTRACT }
```

`taxTag` 取值（增值税归集用，见 06 章）：

| taxTag | 对应科目 | 用途 |
|---|---|---|
| `INPUT_TAX_CERTIFIED` | 应交税费—应交增值税(进项税额) | 已认证可抵扣 |
| `INPUT_TAX_PENDING` | 应交税费—待认证进项税额 | 未认证暂挂 |
| `INPUT_TAX_DEFERRED` | 应交税费—待抵扣进项税额 | 已认证待抵扣 |
| `INPUT_TAX_TRANSFER_OUT` | 应交税费—应交增值税(进项税额转出) | 不得抵扣转出 |
| `OUTPUT_TAX` | 应交税费—应交增值税(销项税额) | 一般计税销项 |
| `OUTPUT_TAX_SIMPLE` | 应交税费—简易计税 | 简易计税 |
| `OUTPUT_TAX_DEFERRED` | 应交税费—待转销项税额 | 收入已确认、纳税义务未发生 |
| `VAT_PAYABLE` | 应交税费—应交增值税 | 归集与转出未交 |
| `VAT_UNPAID` | 应交税费—未交增值税 | 月末转入 |
| `VAT_PAID` | 应交税费—应交增值税(已交税金) | 预缴 |
| `VAT_TRANSFER_OUT_UNPAID` | 应交税费—应交增值税(转出未交增值税) | 月末转出 |
| `VAT_TRANSFER_OUT_MULTI_PAID` | 应交税费—应交增值税(转出多交增值税) | 月末转出 |
| `SURTAX_BASE` | 税金及附加 | 附加税费计提 |

## 3. ② 业务单据

### Document（原始单据文件，只增不改）

```prisma
model Document {
  id           String         @id @default(uuid())
  entityId     String
  docType      DocType        // 用户导入时的声明类型
  detectedType DocType?       // AI 识别出的实际类型（可与声明不符 → 风险提示）
  source       DocSource      // UPLOAD | WATCH_FOLDER | EMAIL | SCAN
  originalName String
  mimeType     String
  sizeBytes    Int
  contentHash  String         // ★ SHA-256，去重与幂等的基础
  storageKey   String         // 存储路径 / 对象存储 key
  pageCount    Int?
  status       DocumentStatus @default(PENDING)
  errorMessage String?
  uploadedBy   String?
  createdAt    DateTime       @default(now())
  @@unique([entityId, contentHash])          // ★ 同一文件不会重复入库
  @@index([entityId, status])
  @@map("document")
}

enum DocType { INVOICE_SALES INVOICE_PURCHASE BANK_SLIP BANK_STATEMENT CONTRACT RECEIPT OTHER }
enum DocSource { UPLOAD WATCH_FOLDER EMAIL SCAN }
enum DocumentStatus { PENDING EXTRACTING EXTRACTED REVIEW_REQUIRED FAILED ARCHIVED }
```

### Partner（往来单位）

```prisma

  name          String                                // 名称（标准化后）
  rawNames      String[]                              // 见过的所有原始写法（用于模糊匹配）

  bankAccount   String?
```

> **匹配优先级**：纳税人识别号（精确）→ 银行账号（精确）→ 名称标准化后精确 → 模糊（编辑距离/包含）。前三档自动，第四档必须人工确认。

### Contract（合同 —— 辅助/备查定位）

```prisma
model Contract {
  id            String    @id @default(uuid())
  entityId      String
  contractNo    String?
  name          String
  counterpartyId String?
  direction     String                        // IN 采购 / OUT 销售
  amountInclTax Decimal   @db.Decimal(18,2)
  taxRate       Decimal?  @db.Decimal(6,4)
  signDate      DateTime? @db.Date
  startDate     DateTime? @db.Date
  endDate       DateTime? @db.Date
  status        String    @default("ACTIVE")  // ACTIVE | FINISHED | TERMINATED
  documentId    String?                       // 合同扫描件
  remark        String?
  @@index([entityId, direction])
  @@map("contract")
}
```

> ⚠️ **合同不产生分录**。它只做三件事：① 关联发票/流水；② 风险比对（合同额 vs 累计开票额）；
> ③ 作为凭证册的附件页码索引。这是用户明确选择的口径，也是「不容易记错」的关键。

### Invoice（发票）

```prisma
model Invoice {
  id                 String        @id @default(uuid())
  entityId           String
  direction          InvoiceDirection   // OUTPUT 销项 | INPUT 进项
  category           InvoiceCategory    // SPECIAL_VAT 专票 | GENERAL_VAT 普票 | E_INVOICE 数电票
                                        // | TRAIN 火车票 | AIR 机票 | TOLL 过路费 | OTHER
  invoiceCode        String?                  // 发票代码（纸质/老电票 10 或 12 位）
  invoiceNumber      String                    // 发票号码（数电票 20 位）
  digitalInvoiceNo   String?                  // 数电票 20 位号码
  invoiceDate        DateTime      @db.Date
  sellerTaxNo        String?
  sellerName         String
  buyerTaxNo         String?
  buyerName          String
  amountExclTax      Decimal       @db.Decimal(18,2)   // 不含税金额（金额）
  taxRate            Decimal       @db.Decimal(6,4)    // 0.13 / 0.09 / 0.06 / 0.03 / 0.01 / 0
  taxAmount          Decimal       @db.Decimal(18,2)   // 税额
  amountInclTax      Decimal       @db.Decimal(18,2)   // 价税合计
  isRedFlushed       Boolean       @default(false)     // 是否红字发票
  originalInvoiceId  String?                           // 红冲指向的原票
  isDeductible       Boolean       @default(true)      // 是否可抵扣（集体福利/个人消费= false → 计入成本）
  businessType       String?                           // PURCHASE_MATERIAL|PURCHASE_SERVICE|EXPENSE|FIXED_ASSET|SALES
  accountId          String?                           // 费用类发票的对方科目（规则引擎或人工指定）
  partnerId          String?
  contractId         String?
  documentId         String?                           // 原始图片/PDF
  extractionId       String?                           // 对应抽取结果
  matchedTransactionId String?                         // 已匹配的银行流水
  status             InvoiceStatus @default(IMPORTED)
  dedupHash          String                            // ★ 归一化后的业务去重键
  createdAt          DateTime      @default(now())
  /// ★ 业务唯一键：同主体 + 同方向 + 同发票代码 + 同发票号码 + 同是否红冲
  @@unique([entityId, direction, invoiceCode, invoiceNumber, isRedFlushed])
  @@index([entityId, invoiceDate])
  @@index([entityId, status])
  @@map("invoice")
}

enum InvoiceDirection { OUTPUT INPUT }
enum InvoiceCategory { SPECIAL_VAT GENERAL_VAT E_INVOICE TRAIN AIR TOLL OTHER }
enum InvoiceStatus {
  IMPORTED        // 已识别，待入账
  AUTO_DRAFTED    // 已自动生成待确认凭证
  POSTED          // 已入账
  MATCHED         // 已匹配收付款
  RECONCILED      // 已完成对账归档
  IGNORED         // 人工标记不入账（需填理由）
  NEEDS_REVIEW    // 置信度低或校验冲突
}
```

**`dedupHash` 归一化规则**：`sha256(entityId|direction|trim(invoiceCode)|trim(invoiceNumber)|isRedFlushed)`。
纸质票无发票代码时降级为 `sha256(entityId|direction|sellerTaxNo|invoiceDate|amountInclTax|invoiceNumber)`。

## 4. ③ 会计内核（最关键的部分）

### JournalVoucher（记账凭证）

```prisma
model JournalVoucher {
  id            String          @id @default(uuid())
  entityId      String
  periodId      String                                   // ★ 冗余存期间，锁期校验快
  voucherWord   String          @default("记")            // 凭证字：记 / 收 / 付 / 转
  voucherNo    Int                                       // 期间内序号，从 1 连续
  voucherDate   DateTime        @db.Date
  status        VoucherStatus   @default(DRAFT)
  totalDebit    Decimal         @db.Decimal(18,2)
  totalCredit   Decimal         @db.Decimal(18,2)
  summary       String                                   // 主摘要
  attachments   Int             @default(0)              // 附件张数（打印凭证册用）
  sourceType    VoucherSource                            // MANUAL | INVOICE | BANK | PAYROLL | CLOSING | OPENING
  sourceId      String?                                  // 来源业务对象 id
  /// ★ 幂等键：同一来源只可能有一张非作废凭证
  idempotencyKey String?
  ruleId        String?                                  // 命中的规则（可追溯）
  ruleReason    String?                                  // ★ 命中理由，写入凭证备注，可解释
  confidence    Decimal?        @db.Decimal(5,4)         // 该凭证整体置信度
  reviewedBy    String?
  reviewedAt    DateTime?
  postedBy      String?
  postedAt      DateTime?
  reversedById  String?                                  // 被哪张凭证红冲
  reversesId    String?                                  // 本张红冲了哪张
  createdAt     DateTime        @default(now())
  lines         JournalLine[]
  @@unique([entityId, voucherWord, fiscalYearOfPeriod, monthOfPeriod, voucherNo])  // 需配合冗余字段，见下
  @@unique([entityId, idempotencyKey])
  @@index([entityId, periodId, status])
  @@index([entityId, voucherDate])
  @@map("journal_voucher")
}

enum VoucherStatus { DRAFT REVIEWING APPROVED POSTED REVERSED VOID }
enum VoucherSource { MANUAL INVOICE BANK PAYROLL CLOSING OPENING }
```

> **序号唯一性的实现细节**：PostgreSQL 的唯一索引无法跨表 join。
> 因此 `JournalVoucher` 冗余两列 `periodYear Int` / `periodMonth Int`，
> 唯一索引建在 `(entityId, voucherWord, periodYear, periodMonth, voucherNo)` 上，由应用层保证与 `periodId` 一致。
> 凭证号分配用独立的 `VoucherSequence` 行锁表，**绝不**用 `MAX(voucherNo)+1`（并发会重号）。

```prisma
model VoucherSequence {
  id            String @id @default(uuid())
  entityId      String
  periodId      String
  voucherWord   String
  nextNo        Int    @default(1)
  @@unique([entityId, periodId, voucherWord])
  @@map("voucher_sequence")
}
```

### JournalLine（分录行）

```prisma
model JournalLine {
  id          String       @id @default(uuid())
  voucherId   String
  entityId    String
  periodId    String
  lineNo      Int
  accountId   String
  direction   BalanceDirection         // DEBIT | CREDIT
  amount      Decimal      @db.Decimal(18,2)   // ★ 恒为正数
  summary     String?                          // 行摘要（缺省继承凭证摘要）
  // 辅助核算
  partnerId   String?
  auxProject  String?
  auxDepartment String?
  contractId  String?
  // 税相关（用于申报表归集与追溯）
  taxRate     Decimal?     @db.Decimal(6,4)
  taxAmount   Decimal?     @db.Decimal(18,2)
  invoiceId   String?
  voucher     JournalVoucher @relation(fields: [voucherId], references: [id], onDelete: Cascade)
  @@index([entityId, periodId, accountId])                  // 科目余额表 / 明细账
  @@index([entityId, accountId, voucherId])
  @@index([invoiceId])
  @@map("journal_line")
}
```

**金额设计决策（为什么不用带符号的单一金额）**

| 方案 | 优点 | 缺点 | 采用 |
|---|---|---|---|
| `debit`, `credit` 两列 | 报表 SQL 最直接 | 每行必有一列为 0/NULL，易写错 | ✗ |
| `direction` + 正数 `amount` | 不会出现负数金额；方向显式，UI 直观 | 报表需 `CASE WHEN` | **✓** |
| 带符号 `amount` | 最紧凑 | 符号约定易错，金额可能变负 → 违反会计直觉 | ✗ |

### AccountBalance（科目余额）

```prisma
model AccountBalance {
  id             String   @id @default(uuid())
  entityId       String
  periodId       String
  accountId      String
  openingDebit   Decimal  @db.Decimal(18,2) @default(0)   // 期初余额
  openingCredit  Decimal  @db.Decimal(18,2) @default(0)
  debitOccurred  Decimal  @db.Decimal(18,2) @default(0)   // 本期借方发生额
  creditOccurred Decimal  @db.Decimal(18,2) @default(0)   // 本期贷方发生额
  closingDebit   Decimal  @db.Decimal(18,2) @default(0)   // 期末余额
  closingCredit  Decimal  @db.Decimal(18,2) @default(0)
  @@unique([entityId, periodId, accountId])
  @@index([entityId, periodId])
  @@map("account_balance")
}
```

> 余额同时存借方和贷方两栏（而不是「一个余额+方向」），与报表和总账的呈现完全一致，取数不用判断方向。
> 正常方向由 `Account.direction` 决定：借方科目余额在 `closingDebit`，贷方科目在 `closingCredit`。
> 反方向余额（如银行存款透支）按负数记入同侧，是允许的，报表会如实呈现。

余额由 `rebuildBalances(entityId, periodId)` 函数**幂等重算**：删除该期间余额 → 由凭证重算 → 滚动下期期初。
任何时候怀疑余额不对，重算一次即可（并会与留存值比对，不一致则告警）。

> **为什么税期要独立**：一般纳税人增值税通常是**月报**，但企业所得税是**季报**，

> 比在 `Period` 上挂一个 `isQuarterEnd` 标志要干净得多，也便于将来支持季报。

## 9. 数据库层强制约束（防御性设计）

应用层可能被绕过（脚本、误操作、未来新入口）。以下用**触发器**做最后防线：

| 触发器 | 时机 | 作用 |
|---|---|---|
| `trg_journal_line_balance` | 凭证状态变为 `POSTED` 前后 | 校验 `SUM(debit) == SUM(credit) > 0`，否则抛异常 |
| `trg_journal_line_period_lock` | `journal_line` INSERT/UPDATE/DELETE | 若所属期间 `status <> 'OPEN'` → 抛异常 |
| `trg_journal_line_leaf_account` | `journal_line` INSERT | 若科目 `isLeaf = false` 或 `isActive = false` → 抛异常 |
| `trg_voucher_amount_sync` | `journal_line` INSERT/UPDATE/DELETE | 自动重算 `journal_voucher.total_debit/total_credit` |
| `trg_journal_line_amount_positive` | `journal_line` INSERT | `amount <= 0` → 抛异常 |
| `trg_audit_immutable` | `audit_log` UPDATE/DELETE | 抛异常（审计日志只追加） |

由 `Entity.bookkeepingEnforced` 开关控制，便于数据导入/修数时临时关闭（**该开关变更本身写审计日志**）。

## 10. 索引与性能预算

数据量预估（单个小主体，5 年）：

| 表 | 量级 |
|---|---|
| journal_voucher | ~3 万 |
| journal_line | ~10 万 |
| invoice | ~5 万 |
| bank_transaction | ~5 万 |
| account_balance | ~5 万（600 科目 × 60 期） |

这个量级 PostgreSQL 单机毫无压力。关键索引已在各模型标注，其中最要紧的三个：

1. `journal_line(entityId, periodId, accountId)` —— 科目余额表、明细账、报表取数全靠它。
2. `invoice(entityId, direction, invoiceCode, invoiceNumber, isRedFlushed)` —— 防重复入账的唯一键。
3. `journal_voucher(entityId, idempotencyKey)` —— 幂等兜底。

## 11. 数据保留与归档

- 原始单据文件：永久保留（凭证册附件、税务稽查举证）。
- `ai_call_log`：保留 12 个月后归档（含成本统计需求）。
- `audit_log`：永久保留。
- 归档策略：按 `fiscal_year` 分区或导出冷存，第一版先不做分区。
