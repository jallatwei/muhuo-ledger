# 01 · 架构与环境分离

## 1. 分层架构

```
┌──────────────────────────────────────────────────────────────┐
│  展示层  apps/web        Vue3 + Element Plus + Vite           │
│          凭证录入/审核 · 单据队列 · 结账向导 · 报表与打印       │
└──────────────────────────┬───────────────────────────────────┘
                           │  HTTP / JSON  (OpenAPI 契约)
┌──────────────────────────▼───────────────────────────────────┐
│  接口层  apps/api  interface/                                 │
│          Controller · DTO 校验(class-validator) · 认证        │
├──────────────────────────────────────────────────────────────┤
│  应用层  application/                                         │
│          用例编排：ImportInvoiceUseCase · PostVoucherUseCase  │
│          ClosePeriodUseCase …  事务边界就在这里                │
├──────────────────────────────────────────────────────────────┤
│  领域层  domain/            ★ 纯逻辑，不依赖 Nest/Prisma       │
│          accounting/  凭证·分录·期间·余额·结账 不变式          │
│          rule-engine/ 条件求值·分录模板渲染·置信度             │
│          tax/         增值税归集·申报表映射                    │
│          reporting/   报表取数·勾稽校验                        │
├──────────────────────────────────────────────────────────────┤
│  基础设施层  infrastructure/                                  │
│          Prisma 仓储 · 文件存储 · AI Provider · OCR Provider   │
│          PDF 渲染 · Excel 读写 · 任务队列 · 日志与审计          │
└──────────────────────────┬───────────────────────────────────┘
                           │
        ┌──────────────────┴───────────────────┐
        │  PostgreSQL 16   (唯一权威数据源)      │
        │  ├ 会计数据：凭证/分录/余额/期间        │
        │  ├ 业务数据：单据/发票/合同/流水        │
        │  ├ 规则数据：规则/科目映射/历史纠错      │
        │  ├ AI 数据：调用日志/抽取结果/置信度     │
        │  └ 作业队列：PostgreSQL 表即队列        │
        │     (FOR UPDATE SKIP LOCKED)           │
        └──────────────────────────────────────┘
                        对象存储/本地卷：原始单据文件
```

### 为什么领域层要独立

会计逻辑的正确性不该依赖框架。`domain/` 里的代码**不 import Nest、不 import Prisma**，
只走仓储接口。好处：

1. 可以用纯单元测试覆盖「借贷平衡」「期末结转」这类要命的逻辑，跑得快、不用起数据库。
2. 未来换 ORM 或加一个 gRPC 入口，领域层不动。

### 为什么第一版不要 Redis / 消息队列

- 作业量级：一个月几百张单据。PostgreSQL 的 `SELECT ... FOR UPDATE SKIP LOCKED` 完全够用，
  且**不引入额外一致性边界**——作业状态和业务数据在同一事务里，不会出现「凭证写了但任务丢了」。
- 后续真需要了，`JobQueue` 是个接口，换 Redis Stream / BullMQ 不动业务代码。

## 2. 环境分离：三个正交维度

「开发环境和软件本体分开」落地成三条规则：

### 维度 A：编排与本体分离

| | 位置 | 内容 |
|---|---|---|
| **软件本体** | `apps/` `packages/` | 只读环境变量，不知道自己跑在哪 |
| **编排** | `docker/` | 怎么把它跑起来；dev/prod/cloud 各一套 |

环境变量清单（唯一的环境耦合面）：

```bash
NODE_ENV=development|production
DATABASE_URL=postgresql://...
PORT=3000
API_BASE_URL=http://localhost:3000/api
CORS_ORIGINS=http://localhost:5173
TZ=Asia/Shanghai
STORAGE_DRIVER=local|s3
STORAGE_LOCAL_ROOT=/data/attachments
AI_PROVIDER=mock|openai-compatible|qwen|deepseek|local
AI_BASE_URL= / AI_API_KEY= / AI_VISION_MODEL= / AI_TEXT_MODEL=
AI_TIMEOUT_MS=60000  AI_MAX_RETRIES=2
OCR_MIN_CONFIDENCE=0.85        # 低于此值强制人工复核
BOOKKEEPING_AUTO_POST=false    # ★ 永远默认 false：自动生成只到「待确认」
JWT_SECRET= / JWT_EXPIRES_IN=
```

### 维度 B：三种运行形态

| 形态 | compose 文件 | 特点 |
|---|---|---|
| **本地开发** | `docker/dev/docker-compose.yml` | PostgreSQL 容器 + API/Web 源码挂载热重载；`AI_PROVIDER=mock`；DB 端口 5433 避免与宿主冲突；内置 pgAdmin 可选 |
| **本地生产化验证** | `docker/prod/docker-compose.yml` | 真实多阶段构建镜像 + Nginx 托管静态资源；用于上线前验收 |
| **云端部署** | `docker/cloud/*.yml` | 云数据库/RDS、对象存储、HTTPS 终止、自动备份、日志采集 |

**关键约束**：`docker/prod` 和 `docker/cloud` 构建出的**镜像是同一个**，只是 compose 的环境变量与依赖不同。
这样才能保证「本地验过的 = 云端跑的」。

### 维度 C：配置与密钥分离

- `.env.*.example` 进版本库（模板），**真实 `.env.*` 进 `.gitignore`**。
- 生产密钥不落盘到镜像：由云密钥管理/环境注入。
- AI API Key 只存在于 API 服务进程，前端永远拿不到。

## 3. 部署形态（云端）

```
                  Internet
                     │
              ┌──────▼───────┐
              │  Nginx / SLB │  HTTPS 终止 · 静态资源 · 反代 /api
              └──────┬───────┘
                     │
        ┌────────────▼─────────────┐
        │  api 容器 (Node 20 slim) │  无状态，可水平扩展
        │  · HTTP 接口             │
        │  · worker 进程(同镜像)   │  识图/批量入账后台作业
        └────────────┬─────────────┘
                     │
        ┌────────────▼─────────────┐
        │  PostgreSQL (云 RDS)     │  每日自动备份 + PITR
        └──────────────────────────┘
                     │
        对象存储 (OSS/COS) 存原始单据
```

**单机也能跑**：小组织直接 `api + postgres + nginx` 三容器在一台 2C4G 机器上，够用。

## 4. 技术选型与理由

| 层 | 选型 | 理由 |
|---|---|---|
| 后端框架 | NestJS 10 | 模块化清晰，DI 便于替换 AI/存储实现；生态成熟 |
| ORM | Prisma 5 | schema 即文档；迁移可版本化；类型安全直通前端 |
| 数据库 | PostgreSQL 16 | `NUMERIC` 精确小数、事务隔离、行锁；JSONB 存 AI 原始结果；`SKIP LOCKED` 当队列 |
| 金额运算 | decimal.js | 精确十进制，杜绝 0.1+0.2 问题 |
| 前端 | Vue3 + Vite + Element Plus | 国内财务类后台主流；`el-table` 做分录录入顺手；中文表格/打印生态好 |
| 状态 | Pinia | 轻量够用 |
| 后端 PDF | Puppeteer(HTML→PDF) | 凭证册用 HTML/CSS 排版，同一份模板还能直接浏览器打印 |
| Excel | exceljs | 读银行流水、写申报表底稿 |
| 文档解析 | pdf-parse / sharp | PDF 取文本与转图 |
| 测试 | Vitest(单测) + Testcontainers(集成) | 领域层纯单测，仓储层起真 PG |
| 日志 | pino | 结构化日志，便于云端采集 |

## 5. 安全与合规底线

1. **认证**：JWT + 短期 access token；密码 bcrypt(cost=12)。
2. **审计**：`audit_log` 表记录所有写操作（谁、何时、改了什么、改前改后），**只追加不修改**。
3. **数据不外泄**：AI 识图发给第三方前，可选「脱敏模式」——只发必要字段区域裁剪图，隐去银行账号/身份证。
4. **可离线**：`AI_PROVIDER=mock|local` 时系统完全离线运行，满足隐私敏感场景。
5. **备份**：本地 `pg_dump` 每日；云端 RDS 自动备份。原始单据文件与数据库**同批次备份**，否则凭证册打印不出附件。
