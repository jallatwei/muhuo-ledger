### T-D 期间与凭证内核

| # | 用例 | 期望 |
|---|---|---|
| T20 | 借贷不平 | 抛 `UnbalancedVoucherError`，**不落库** |
| T21 | 金额为 0 或负 | 抛错 |
| T22 | 非末级科目记账 | 抛 `NonLeafAccountError` |
| T23 | 已结账期间写凭证 | 抛 `PeriodLockedError`；**DB 触发器也拒绝** |
| T24 | 凭证号连续性 | 过账 10 张 → 号 1~10 无空洞；删草稿不影响号段 |
| T25 | 并发分配凭证号 | 10 个并发过账 → 号不重复、不跳号 |
| T26 | 幂等生成 | 同一发票调用 3 次自动记账 → 只有 1 张凭证，后 2 次返回 `alreadyGenerated=true` |
| T27 | 红冲 | 红冲后原凭证 `REVERSED`，**两者分录合计净额为 0**，余额归零 |
| T28 | 重复导入同一发票 | 第二次导入不产生新发票，只补 `DocumentLink` |

### T-F 属性测试（防未来笔误）

```ts
// 对随机生成的 1000 张票据，断言任何规则产出的分录都借贷平衡
it('任意规则产出的分录必须借贷平衡', () => {
  fc.assert(fc.property(arbitraryInvoice(), (inv) => {
    const r = engine.evaluate(ctxOf(inv));
    return sumDebit(r.lines).eq(sumCredit(r.lines));
  }));
});
```

## 4. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| **AI 识图准确率不足** | 大量人工返工，不如手工录 | 交叉校验先拦错；Mock + 真实样例双跑评估；支持换 Provider；关键字段人工必看 |
| **规则漏配导致乱记账** | 记错账 | 未命中宁可强制人工，**绝不猜科目**；`autoPost` 默认永久关闭 |
| **税务政策变化** | 申报表出错 | 税率/优惠/行次全部配置化，UI 标注政策文号与生效期；不硬编码 |
| **申报表无法自动导入税局** | 用户预期落差 | 明确采用"底稿模式"，字段与行次与税局完全一致；预留 `TaxExportProvider` |
| **凭证册打印排版复杂** | 返工 | 同一 HTML 模板两处复用（屏幕/PDF）；先做 2 张/页固定版式 |
| **金额精度问题** | 差 1 分导致不平 | 全链路 `Decimal`；`round(2)` 统一在一处；属性测试覆盖 |
| **并发凭证号重复** | 号段冲突 | `VoucherSequence` 行锁；T25 并发测试 |
| **范围蔓延** | 做不完 | 明确排除清单（00 章第 2 节）；固定资产/工资/存货计价后续单开 |
| **单人使用无第二双眼睛** | 错误无人发现 | 结账检查清单 + 风险扫描 + 账务自检，让系统充当"复核人" |
